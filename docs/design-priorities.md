# 设计重点

## 按评审维度倒推

| 维度 | 产品机制 | MVP 验收方式 |
|---|---|---|
| 产品完整度 | 项目用途、报价源、任务路由、报告、反馈/测评闭环 | 运行 CLI 和三条离线测评用例 |
| 支付/交付完整度 | 本版交付 CLI/API、成本估算和可复核 Markdown；支付未纳入 | 报告包含价格来源、采集时间、单次成本假设与报告 ID |
| 商业表现 | 免费的透明价格/来源入口 + 可复用项目推荐，后续按任务规划/报告服务收费 | 不影响核心框架；支付和计费接入需正式产品接口后再做 |
| 作品影响力 | 报告可被审阅与分享，价格来源有链接，数据过期有提示 | 本地生成 Markdown，不要求厂商账户才能阅读 |

## 产品策略

- L1 比价入口：厂商与模型价目、统一 token 单位、来源时间、成本假设；公开数据用于获客，不把链接集合包装成独家能力。
- L2 任务规划：项目用途 → 步骤类型 → 每步模型和成本；本版以规则/权重显式推荐，降低幻觉和调试成本。
- L3 模板执行：先定义翻译、摘要、批量改写三个任务模板的输入输出合同；此 MVP 只推荐模型和成本，不代替生产执行工作流。
- 共用评价引擎：价格权重与业务测评分开记录，不能把模型宣传指标混为自有实测。

## 信任与价格意愿

1. 付费前先说明任务规模、成本估算和数据来源。
2. 每份报告可追溯至报价快照、更新时间和推荐评分。
3. 免费层可保留入口和基本对比；高频用户可以通过订阅/按量服务获取持续更新、项目分析和可复用工作流。实际价格、支付和商业政策应在产品运营评估后决定。
