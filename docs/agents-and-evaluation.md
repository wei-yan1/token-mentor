# Agent 工作流与持续评估

## 三个 agent

### MarketResearchAgent

按配置调用阿里云、DeepSeek 等价格 MCP 和 Tavily 等搜索 MCP。`run_once()` 可由 CLI 手动调用，`run_forever(interval_seconds=...)` 可由受监督进程循环调用。每源独立隔离异常。价格工具输出规范报价，新厂商搜索结果进入 discovery；人工核实价格后才转成价格记录。

### ProjectAdvisorAgent

使用用户意图优先的项目画像，把任务拆成代码、推理、翻译、摘要、改写和通用问答等角色，再按实际输入输出 token 估算、项目权重和有来源的数据推荐模型。也基于可识别的技术栈给数据库/缓存建议。只生成 Markdown/API 结果，不执行客户项目代码。

### EvaluationAgent

对固定测评集跑意图类别识别与报价模型排序，作为规则/权重变更的回归门。运行命令：`token-mentor eval --cases evals/cases.json`。

## 小测评集设计

每条 case 至少包含：稳定 ID、自然语言意图、预期任务类别、报价快照、预期首选模型。覆盖成本优先、质量优先、稳定优先、多任务项目和无评分维度等场景。示例报价是合成夹具，绝不可用于线上价格展示。

建议指标：

- 任务分类召回/准确（当前命令输出单条 pass 与整体 pass rate）。
- 首选模型命中率和 NDCG@k（MVP 当前检查首位命中；后续添加排序指标）。
- 每任务估算成本与成功率；实际调用延迟、失败率和质量须从可复现的供应商测评采集。
- 反馈评分按任务、场景分组，避免不同业务混成一个均值。

## 反思回路

1. 收集报告反馈、线上成本、失败率及人工金标准。
2. 将可复现案例并入测评集，写清预期结果与理由。
3. 调整任务线索、能力标签或权重，在全量案例上跑离线评估。
4. 人工审核报告变化后发布规则；如果表现下降，回滚配置。

MVP 只保存反馈，不会基于少数评价自动学习或更改线上权重。此限制防止一次主观意见造成所有用户的推荐漂移。
